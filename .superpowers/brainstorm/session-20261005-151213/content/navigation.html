导航寻路系统

页面图谱上的 BFS 寻路，边的可通行性与动作统一声明

导航边（Edge）数据模型

sealed class Edge {
  string From;         // 起始页面 Id
  string To;           // 目标页面 Id
  Action[] Actions;    // 执行的动作序列
  Func<Ctx,bool>? Condition; // 可选：边可用条件
  int Cost;           // 寻路代价（默认1，长路径可设高）
}

Action = { Type: press|dpad|wait, Button?, Direction?, Ms? }

寻路流程（单点规则复用）

单点规则：
  IsTraversable(edge, ctx) = edge.Condition == null || edge.Condition(ctx)
  IsGoal(page, target) = page == target

寻路（BFS/Dijkstra over edges）：
  path = BFS(from=currentPage, to=targetPage,
          neighbors=edges.Where(e => e.From==current && IsTraversable(e)))

执行：
  for edge in path:
    for action in edge.Actions: action.Execute()
    observe() # 验证到达 edge.To
    if not arrived: 回退 / 重试

半途接续（不强制回主页）

当前页面 = match_hub，目标 = myleague_home
旧代码：EnterMyLeagueAsync 手写判断「已在比赛菜单则 Right×2」
新系统：BFS(match_hub → myleague_home) = [match_hub→myleague_home]
  直接执行这条边，无需回主页。

寻路天然支持「从任意页面到任意页面」，无需手写半途逻辑。

优势

  • 新增页面只需加 PageNode + Edge，自动可寻路
  • 半途接续免费：BFS 从当前页出发
  • Condition 支持条件边（如只在需要买道具时走商店边）
  • 边的动作可复用（如「按 A 等待」封装为 Action）

注意

  • 执行后必须验证到达目标页（防操作失效）
  • 找不到路径时需兜底（回主页重试 / 报错）
  • MatchFlow 是特殊节点，入边=开赛，出边=完赛回主页
