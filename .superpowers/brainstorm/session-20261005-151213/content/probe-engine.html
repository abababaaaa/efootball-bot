探针引擎（Probe Engine）判定逻辑

统一命中口径 + 分离原始指标与综合分 + 禁止早返回强制策略

探针类型（3 种原子探针 + 1 种组合）

① OcrProbe
输入: OCR 结果
规则: 关键词列表 [{text, weight, region?}]
输出: rawScore = Σ weight（命中词）
阈值: minScore（原始分硬阈值）
② VisualProbe
输入: 帧像素
规则: ROI + HSV 滤镜
输出: rawRatio = 命中像素占比
阈值: minRatio（原始占比硬阈值）
③ CompositeProbe
组合: OcrProbe AND/OR VisualProbe
输出: 各子探针 raw 值
用途: InMatch 需「草皮 AND (机器人图标 OR 时钟)」
④ Override 标记
不是早返回，而是写入结果对象：
result.Override = "reward-popup"
由统一出口消费，不中断其他探针计算

判定流程（无早返回，统一出口）

1. 并行计算所有 PageNode 的探针 → 得到 Candidate[]
    每个 Candidate: { page, rawOcrScore, rawVisuals[], evidence[] }

2. 计算 Override（强制覆盖）信号：
    - reward-popup → override = MyLeagueHome
    - loading-spinner → override = Loading
    写入 result.Override，不中断

3. 迟滞状态（Hysteresis）：
    若 holdMatch=true，检查强退出信号（赛后画面≥阈值 / Dialog≥3 / 菜单≥4）
    无强退出 → 维持 InMatch

4. 冲突消解（Priority 规则，声明式）：
    按声明的优先级排序，高优先级候选压制低优先级

5. 统一出口返回：
    result = { screen, rawScore, evidence, override, holdMatch }
    所有字段完整，调用方按需消费

冲突消解（声明式 Priority，非字典删键）

每个 PageNode 声明 Priority 数值，引擎按优先级排序：

高优先级（先判定，命中则压制低优先级）：
  Loading(spinner) · Disconnected · ActivityDetail · EventSettings
  ChallengeHome · EventInfo · ChallengeList · NoEvent · CampaignBoard

中优先级：
  MyLeagueHome · PreMatch · Shop · InMatch

低优先级：
  MatchHub · EventHub · Home · Dialog

同优先级按 rawScore 降序。证据门（如 MyLeagueHome 需强特征词）作为 Probe 的 minScore 实现。

对比当前代码的改进

  • 无早返回：所有探针都计算，证据完整可追溯
  • rawScore 与 composite 分离：阈值只基于原始分
  • Priority 声明式：新增页面只需设优先级，不改消解代码
  • 迟滞状态独立：holdMatch 作为状态字段，不混入打分

注意事项

  • Override 信号（弹窗/spinner）仍需特殊处理，但通过结果对象传递
  • VisualProbe 的 ROI 和滤镜需要一个注册表
