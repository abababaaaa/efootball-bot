页面图谱数据模型

核心三层：底层页（BasePage）+ 覆盖层（Overlay）+ 导航边（Edge）

分层结构

BasePage（底层页）
Id: myleague_home
Probes: [OCR 前往比赛×2.5, 下一场×2.5]
Actions: [清弹窗→买道具→开赛]
Edges: →schedule, →shop
游戏的稳定画面，参与导航寻路
Overlay（覆盖层）
Id: dialog_ok
Probes: [OCR 确定×1.5]
Dismiss: PressButton(确定)
弹窗/断线/奖励，可叠在任意底层页上，优先处理
Edge（导航边）
From: home
To: match_hub
Action: Down×2→Left×2→A
Condition: (可选)
有向边，引擎自动寻路

引擎主循环（极简）

while (!cancel):
  obs = observe()         # 捕获帧 + OCR
  overlay = matchOverlay(obs) # 优先匹配覆盖层
  if overlay: overlay.dismiss(); continue
  page = matchPage(obs)      # 匹配底层页
  page.executeActions()      # 执行该页声明的动作
  if needNav: path = graph.findPath(page, target)
            for edge in path: edge.execute()

为什么分底层页/覆盖层

  • 弹窗可出现在任意页面，不参与导航图
  • 覆盖层优先级更高，先清弹窗再处理页面
  • 当前代码里 HandlePopups / PassThrough 散落各处，统一为 Overlay 层

需要注意

  • 比赛中(InMatch)是长流程，不是简单页面
  • 部分页面有条件分支（如关键比赛 vs 普通比赛）
