比赛流程（MatchFlow）状态机

独立于页面图谱的子状态机，封装赛前→开球→比赛中→结算全流程

Flow 与 PageGraph 的关系

PageGraph 只管：
  [myleague_home] --(前往比赛)--> [MatchFlow]
  [MatchFlow] --(完赛)--> [myleague_home]

MatchFlow 内部自管 7 个阶段：
  PreMatch → Kickoff → Playing → Halftime → FullTime → Result → Rewards → Exit

7 个阶段（Stage）

① PreMatch 赛前
进入: 页面跳转到赛前设置
动作: 确认难度 → 按「开始比赛」
退出: 检测到 InMatch 或 Loading
② Kickoff 等待开球
动作: 连续 2 次确认 InMatch（过滤入场动画误判）
退出: 连续 2 次 InMatch
超时: ~18s 后按当前画面继续
③ Playing 比赛中
动作: 跳过回放/暂停菜单按钮 + 随机轻按 A（防检测）
死线: 每次 InMatch 顺延 MatchTimeoutMin（滑动超时）
退出: Result/Rewards/FullTime 或稳定菜单页
④ Halftime 中场
动作: 按 A 继续
退出: 回到 InMatch 或进入 FullTime
⑤ FullTime 全场结束
动作: 按 A → 等待 2.5s
退出: Result 页面
⑥ Result 结果/MVP
动作: 按 A 跳过
退出: Rewards 或稳定菜单页
⑦ Rewards 奖励页 → Exit 退出
动作: 逐个按 A 跳过奖励弹窗（使用 PressButton 识别焦点）
退出: 连续 3 帧画面稳定 → 返回 PageGraph（回到主页/列表）
特殊: 国际服 CampaignBoard 棋盘页需右移光标再按 A

弃权分支（仅普通比赛·只踢关键模式）

Playing 阶段可插入 Forfeit 子流程：
  Start 键 → 找「放弃比赛」→ 确认弹窗 → 完成
  失败 → 回到 Playing 正常完赛

设计要点

  • Flow 有独立的滑动超时（每次 InMatch 顺延死线）
  • 比赛中弹窗（回放/暂停/换人）由 Playing 阶段内的动作处理，不污染 PageGraph
  • 完赛后回到调用前页面，PageGraph 接续

与当前代码的对应

  • PlayOneMatchAsync → MatchFlow 引擎
  • PostMatchSequenceAsync → Rewards 阶段
  • TryForfeitAsync → Forfeit 子流程
